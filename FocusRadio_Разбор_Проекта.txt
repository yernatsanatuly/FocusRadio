================================================================================
FOCUSRADIO — СОВМЕСТНЫЕ КОМНАТЫ ДЛЯ РАБОТЫ И УЧЕБЫ (VIRTUAL COWORKING SPACE)
ПОЛНЫЙ РАЗБОР ПРОЕКТА, АРХИТЕКТУРЫ И КАЖДОГО ФАЙЛА (ДЛЯ КОМАНДЫ ИЗ 3 ЧЕЛОВЕК)
================================================================================

О ПРОЕКТЕ:
FocusRadio — это REST API интерактивного виртуального коворкинга на FastAPI.
Сервис помогает студентам, фрилансерам и разработчикам бороться с прокрастинацией,
организовывать рабочее время и удерживать фокус с помощью:
  1) Виртуальных коворкинг-комнат (публичных и приватных по пин-коду);
  2) Гибких таймеров фокуса (Pomodoro, Short, Deep Work, Custom) и личных задач;
  3) Адаптивного радио (подбор музыки под текущую фазу комнаты: фокус или перерыв);
  4) Визуальной геймификации (опыт XP, уровни, ежедневные стрики, ачивки, лидерборды).


================================================================================
1. КАК РАБОТАЕТ СИСТЕМА В ЦЕЛОМ (ПОТОК ЗАПРОСА)
================================================================================

В проекте реализована многослойная архитектура (Layered Architecture), где
каждый слой отвечает строго за свою задачу:

  HTTP-запрос клиента (Swagger UI / Frontend)
         │
         ▼
  1. Routers (app/routers/*)
     Принимает маршрут, query/path параметры и заголовок X-User-Id.
         │
         ▼
  2. Schemas (app/schemas/*)
     Валидирует входной JSON через Pydantic v2 (типы, regex, ограничения).
         │
         ▼
  3. Dependencies (app/core/dependencies.py)
     Через FastAPI Depends создает нужный Service и передает ему In-Memory БД.
         │
         ▼
  4. Services (app/services/*)
     Выполняет всю бизнес-логику, проверяет права, считает таймеры, XP и ачивки.
         │
         ▼
  5. Entities & DB (app/models/* + app/core/database.py)
     Читает и изменяет dataclass-объекты в оперативной памяти, сохраняя связи.
         │
         ▼
  HTTP-ответ (JSON по Pydantic-схеме или единый JSON ошибки через Exception Handler)

3. ПОДРОБНЫЙ РАЗБОР КАЖДОГО ФАЙЛА

--------------------------------------------------------------------------------
А. КОРНЕВЫЕ ФАЙЛЫ И ТОЧКА ВХОДА
--------------------------------------------------------------------------------

1) app/main.py — Главная точка входа FastAPI
   - Функция lifespan(): запускается при старте сервера и автоматически заполняет
     базу демо-данными (seed_demo_data), чтобы в Swagger сразу были пользователи,
     комната и треки.
   - Инициализация объекта FastAPI с описанием для интерактивной документации
     Swagger (/docs) и ReDoc (/redoc).
   - Подключение CORSMiddleware.
   - Регистрация глобальных обработчиков ошибок register_exception_handlers(app).
   - Подключение 6 роутеров (users, rooms, sessions, tasks, tracks, leaderboard)
     и корневого эндпоинта GET / для проверки статуса сервера.

2) app/config.py — Конфигурация и бизнес-правила
   - Класс Settings хранит все константы и правила:
     * seconds_per_minute = 60 (можно переопределить через переменную окружения
       FOCUSRADIO_SECONDS_PER_MINUTE=1, чтобы на защите 25-минутный таймер
       проходил за 25 секунд!).
     * Лимиты: максимум 3 паузы за сессию (max_pauses_per_session = 3),
       длительность фокуса от 1 до 180 минут.
     * Награды XP:
       - 2 XP за каждую минуту полного фокуса;
       - 1 XP за минуту при досрочном завершении;
       - +20 XP бонус за полное завершение таймера;
       - +10 XP бонус за сессию без единой паузы;
       - +5 XP за каждого соседа по комнате, который тоже фокусируется;
       - +5 XP за каждый день стрика (до 10 дней);
       - +15 XP за выполненную задачу.


--------------------------------------------------------------------------------
Б. ЯДРО ПРИЛОЖЕНИЯ (app/core/)
--------------------------------------------------------------------------------

3) app/core/database.py — In-Memory база данных
   - Класс Database хранит 5 словарей: users, rooms, tracks, tasks, sessions.
   - Метод next_id(collection) генерирует автоинкрементные ID (1, 2, 3...).
   - Метод reset() полностью очищает базу (используется в автотестах).
   - Функция seed_demo_data() при старте создает:
     * 10 аудиотреков разных жанров и настроений;
     * 3 пользователей: Alice (id=1), Bob (id=2), Carol (id=3);
     * Публичную комнату "Morning LoFi Library" (id=1), где сидит Alice и играет
       первый Lo-Fi трек.

4) app/core/exceptions.py — Доменные исключения и единый формат ошибок
   - Все ошибки API возвращаются в едином JSON-формате:
     {
       "error": {
         "code": "КОД_ОШИБКИ",
         "message": "Понятное описание проблемы",
         "details": { ... }
       }
     }
   - Классы исключений:
     * NotFoundError -> 404 Not Found (ресурс не найден);
     * ForbiddenError -> 403 Forbidden (чужой ресурс или неверный код комнаты);
     * ConflictError -> 409 Conflict (комната заполнена, сессия уже идет, дубликат);
     * BusinessRuleError -> 422 Unprocessable Content (нарушено бизнес-правило);
     * RequestValidationError -> 422 (ошибка валидации полей Pydantic).

5) app/core/dependencies.py — Внедрение зависимостей (Dependency Injection)
   - ActingUserId: читает обязательный заголовок X-User-Id (целое число >= 1),
     который указывает, от имени какого пользователя выполняется операция.
   - Limit и Offset: стандартные query-параметры пагинации списков.
   - Функции get_user_service, get_room_service, get_session_service,
     get_task_service, get_track_service автоматически создают нужный сервис
     и передают его в эндпоинты роутеров.


--------------------------------------------------------------------------------
В. ВНУТРЕННИЕ МОДЕЛИ ДАННЫХ (app/models/)
--------------------------------------------------------------------------------

6) app/models/enums.py — Перечисления (Enums)
   - SessionMode: pomodoro (25/5), short (15/3), deep_work (50/10), custom.
   - SessionStatus: active, paused, completed, ended_early, cancelled.
   - Genre: lofi, ambient, nature, classical, white_noise, synthwave.
   - Mood: focus, break, energize, calm.
   - TaskStatus: todo, in_progress, done.
   - TaskPriority: low, medium, high.
   - LeaderboardMetric: xp, focus_minutes, streak, sessions.

7) app/models/entities.py — Сущности базы данных (Dataclasses)
   - Отделены от Pydantic-схем, чтобы внутренние поля не утекали в API:
     * User: профиль, xp, total_focus_minutes, completed_sessions,
       completed_tasks, current_streak, longest_streak, last_focus_date,
       словарь открытых ачивок achievements и current_room_id.
     * Room: название, owner_id, capacity, is_private, секретный access_code,
       preferred_genre, tags, список участников member_ids, current_track_id.
     * Track: название, артист, жанр, настроение (mood), энергия (1..10),
       длительность в секундах, BPM.
     * Task: задача пользователя, приоритет, статус, оценка в помидорках
       (estimated_pomodoros), выполненные помидорки (completed_pomodoros)
       и флаг xp_awarded (чтобы нельзя было фармить XP переоткрытием задачи).
     * FocusSession: таймер пользователя, привязка к комнате и задаче, время
       старта, количество пауз, суммарные секунды пауз и заработанный XP.


--------------------------------------------------------------------------------
Г. PYDANTIC-СХЕМЫ ВАЛИДАЦИИ (app/schemas/)
--------------------------------------------------------------------------------

8) app/schemas/common.py
   - Page[T]: универсальная схема пагинации (items, total, limit, offset).
   - ErrorResponse и error_responses(): описание ошибок для документации Swagger.

9) app/schemas/users.py
   - UserCreate: валидирует username (3-30 символов, только буквы/цифры/_),
     проверяет формат email через регулярное выражение и переводит их в нижний регистр.
   - UserUpdate: схема частичного обновления (PATCH), запрещает пустой запрос {}.
   - LevelInfo, UserResponse, AchievementResponse, UserStats: выходные схемы
     профиля и подробной статистики продуктивности.

10) app/schemas/rooms.py
    - RoomCreate: нормализует теги (нижний регистр, без дублей, до 5 штук),
      проверяет вместимость (2..50). Валидатор check_privacy() требует
      access_code (4-12 символов) для приватных комнат и запрещает его для публичных.
    - RoomResponse: возвращает комнату с вычисляемыми полями member_count,
      available_spots и текущим треком current_track (скрывая секретный access_code).
    - RoomActivity и RoomMember: показывают всех людей в комнате, их живой статус
      (focusing / paused / idle), остаток секунд таймера и общую фазу комнаты.
    - TrackRecommendation и LeaveRoomResult: ответы адаптивного радио и выхода.

11) app/schemas/sessions.py
    - SessionCreate: проверяет режим таймера. Для пресетов (pomodoro, short,
      deep_work) запрещает ручной ввод минут; для custom требует focus_minutes
      и проверяет, что break_minutes <= focus_minutes.
    - SessionResponse: включает живые расчетные поля таймера:
      elapsed_focus_seconds, remaining_seconds, progress_percent, is_time_up.
    - SessionFinishResult: возвращается при завершении сессии — содержит чек
      начисленного опыта (xp_breakdown), новый уровень, флаг leveled_up,
      текущий стрик и список новых открытых достижений.

12) app/schemas/tasks.py, app/schemas/tracks.py, app/schemas/leaderboard.py
    - TaskCreate / TaskUpdate / TaskResponse: валидация задач и расчет процента
      выполнения по помидоркам.
    - TrackCreate / TrackUpdate / TrackResponse: валидация энергии (1..10),
      длительности (30..7200 сек) и BPM (40..220).
    - Leaderboard / LeaderboardEntry: схемы глобального и комнатного рейтинга.


--------------------------------------------------------------------------------
Д. БИЗНЕС-ЛОГИКА — СЕРВИСЫ (app/services/)
--------------------------------------------------------------------------------

Вся сложная логика вынесена сюда из роутеров:

13) app/services/common.py — Общие проверки
    - Функции get_user, get_room, get_track, get_task, get_session находят объект
      в БД или сразу выбрасывают 404 NotFoundError.
    - find_active_session() ищет запущенный или стоящий на паузе таймер пользователя.
    - ensure_actor_exists() и ensure_same_user() проверяют заголовок X-User-Id
      и защищают чужие данные от изменения (403 Forbidden).

14) app/services/gamification.py — Движок геймификации (Сценарий №3)
    - Система уровней: порог XP для уровня L считается по квадратичной формуле:
      XP(L) = 50 * (L - 1) * L
      (Уровень 1 = 0 XP, Уровень 2 = 100 XP, Уровень 3 = 300 XP и т.д.).
      В зависимости от уровня присваивается титул: Listener -> Apprentice ->
      Focused Mind -> Deep Worker -> Flow Master -> Zen Legend.
    - 11 автоматических достижений (ACHIEVEMENTS):
      * first_tune_in — завершить 1-ю сессию;
      * in_the_groove — завершить 5 сессий;
      * focus_machine — завершить 20 сессий;
      * hour_club — набрать 60 минут фокуса;
      * deep_diver — завершить сессию на 50+ минут за раз;
      * laser_focus — завершить сессию 25+ минут без единой паузы;
      * better_together — завершить сессию, пока 2+ соседей по комнате тоже фокусируются;
      * on_fire — стрик 3 дня подряд;
      * unstoppable — стрик 7 дней подряд;
      * task_master — закрыть 5 задач;
      * level_5 — достичь 5-го уровня.
    - Стрики и награды: update_streak() ведет учет непрерывных дней,
      reward_session() считает полный XP и бонусы, а build_leaderboard()
      сортирует участников с учетом ничьих (одинаковый результат = одинаковое место).

15) app/services/room_service.py — Коворкинг и Адаптивное Аудио (Сценарий №1)
    - Создание комнаты: проверяет уникальность имени и то, что создатель не сидит
      в другой комнате. Создатель автоматически входит в комнату.
    - Вход (join): проверяет лимит мест (409 ROOM_FULL), пин-код приватной
      комнаты (403 INVALID_ACCESS_CODE) и переносит активную сессию пользователя
      в эту комнату.
    - Выход и кик (remove_member / detach_member):
      * Участник может выйти сам, а владелец комнаты может исключить (кикнуть) участника.
      * Если из комнаты выходит владелец, права владельца (owner_id) автоматически
        передаются следующему старейшему участнику комнаты!
      * Если комнату покидает последний человек, она автоматически закрывается
        и удаляется из памяти.
    - Адаптивное радио (recommend_tracks):
      * Считает, сколько участников комнаты сейчас находятся в активной сессии фокуса.
      * Если >= 50% участников фокусируются -> фаза комнаты "focus": рекомендуются
        спокойные треки (mood: focus/calm, энергия <= 5).
      * Если большинство отдыхает -> фаза комнаты "break": рекомендуются бодрящие
        треки (mood: break/energize) для перезагрузки.
      * В обоих случаях приоритет отдается любимому жанру комнаты (preferred_genre).

16) app/services/session_service.py — Таймеры фокуса (Сценарий №2)
    - Машина состояний: ACTIVE <-> PAUSED -> COMPLETED / ENDED_EARLY / CANCELLED.
    - Точный расчет времени: elapsed_focus_seconds() вычитает из прошедшего времени
      все секунды, проведенные на паузе.
    - Старт (start): проверяет, что у пользователя нет другого активного таймера
      (иначе 409 SESSION_ALREADY_RUNNING). Если привязана задача со статусом todo,
      автоматически переводит её в in_progress.
    - Пауза (pause): разрешает не более 3 пауз за одну сессию (иначе 422 PAUSE_LIMIT_REACHED).
    - Завершение (complete):
      * Если запланированное время истекло — сессия получает статус completed,
        начисляется полный XP + бонусы, а привязанной задаче прибавляется +1 помидорка.
      * Если время еще НЕ вышло — обычный вызов вернет 409 FOCUS_TIME_NOT_REACHED
        с остатком секунд. Но если передать параметр ?force=true, сессия завершится
        досрочно (ended_early) с частичным XP за фактически отработанные минуты.

17) app/services/task_service.py — Личные задачи
    - Сортирует задачи: сначала открытые по важности (high -> medium -> low), затем закрытые.
    - Запрещает дубликаты открытых задач с одним названием и блокирует удаление
      задачи, по которой прямо сейчас запущен таймер (409 TASK_IN_ACTIVE_SESSION).
    - При переводе задачи в статус done начисляет +15 XP и проверяет ачивки.

18) app/services/track_service.py — Каталог аудиотреков
    - Фильтрация по жанру, настроению, минимальной/максимальной энергии и поиск.
    - Защита удаления: если трек сейчас играет в комнате, без флага ?force=true
      вернется 409 TRACK_IN_USE; с ?force=true плеер в комнатах остановится и трек удалится.

19) app/services/user_service.py — Пользователи и аналитика
    - Регистрация, редактирование профиля, агрегация полной статистики (/stats).
    - Каскадное удаление (delete): при удалении аккаунта корректно выводит
      пользователя из комнаты (передавая права владельца), отменяет активный
      таймер и очищает его задачи и сессии.


--------------------------------------------------------------------------------
Е. РОУТЕРЫ FASTAPI (app/routers/) — ВСЕ 34 ЭНДПОИНТА
--------------------------------------------------------------------------------

20) app/routers/users.py (/users)
    - POST   /users                      — Регистрация пользователя
    - GET    /users                      — Список пользователей (поиск, сортировка)
    - GET    /users/{user_id}            — Профиль пользователя
    - PATCH  /users/{user_id}            — Обновить свой профиль (X-User-Id)
    - DELETE /users/{user_id}            — Удалить аккаунт каскадно (X-User-Id)
    - GET    /users/{user_id}/stats      — Подробная статистика продуктивности
    - GET    /users/{user_id}/achievements — Список всех ачивок пользователя

21) app/routers/rooms.py (/rooms)
    - POST   /rooms                      — Создать комнату (владелец входит сразу)
    - GET    /rooms                      — Поиск комнат (по жанру, тегу, свободным местам)
    - GET    /rooms/{room_id}            — Информация о комнате и текущем треке
    - PATCH  /rooms/{room_id}            — Изменить настройки комнаты (только владелец)
    - DELETE /rooms/{room_id}            — Закрыть комнату (только владелец)
    - GET    /rooms/{room_id}/members    — Участники комнаты и их живой фокус-статус
    - POST   /rooms/{room_id}/members    — Войти в комнату (с пин-кодом для приватных)
    - DELETE /rooms/{room_id}/members/{user_id} — Выйти из комнаты или кикнуть участника
    - PUT    /rooms/{room_id}/track      — Поставить трек в комнате (участники)
    - DELETE /rooms/{room_id}/track      — Остановить музыку в комнате
    - GET    /rooms/{room_id}/recommended-tracks — Адаптивный подбор треков под фазу комнаты
    - GET    /rooms/{room_id}/leaderboard — Рейтинг участников внутри комнаты

22) app/routers/sessions.py (/sessions)
    - POST   /sessions                   — Запустить таймер фокуса
    - GET    /sessions                   — История сессий (фильтры по user, room, status, mode)
    - GET    /sessions/{session_id}      — Живое состояние таймера (остаток секунд, прогресс)
    - PATCH  /sessions/{session_id}      — Обновить заметки или привязанную задачу
    - DELETE /sessions/{session_id}      — Удалить завершенную сессию из истории
    - POST   /sessions/{session_id}/pause    — Поставить таймер на паузу (до 3 раз)
    - POST   /sessions/{session_id}/resume   — Снять таймер с паузы
    - POST   /sessions/{session_id}/complete — Завершить сессию и получить XP/ачивки
    - POST   /sessions/{session_id}/cancel   — Отменить сессию (без XP)

23) app/routers/tasks.py (/tasks)
    - POST   /tasks                      — Создать задачу с оценкой в помидорках
    - GET    /tasks                      — Список задач (фильтры по user, status, priority)
    - GET    /tasks/{task_id}            — Детали задачи
    - PATCH  /tasks/{task_id}            — Обновить или завершить задачу (status=done -> +XP)
    - DELETE /tasks/{task_id}            — Удалить задачу

24) app/routers/tracks.py (/tracks)
    - POST   /tracks                     — Добавить трек в каталог
    - GET    /tracks                     — Каталог треков (фильтры по genre, mood, energy)
    - GET    /tracks/{track_id}          — Детали трека
    - PATCH  /tracks/{track_id}          — Обновить метаданные трека
    - DELETE /tracks/{track_id}          — Удалить трек

25) app/routers/leaderboard.py (/leaderboard)
    - GET    /leaderboard                — Глобальный рейтинг (по xp, focus_minutes, streak, sessions)

26) tests/test_api.py
    - Содержит 5 больших интеграционных тестов через FastAPI TestClient:
      1. Проверка запуска сервера, Swagger (/docs) и схемы OpenAPI.
      2. CRUD пользователей, проверка ошибок 409 (дубликат логина), 422 (неверный
         email) и 403 (попытка изменить чужой профиль).
      3. Полный цикл приватной комнаты: проверка пин-кода, смена музыки, адаптивные
         рекомендации треков, автопередача прав владельца при выходе создателя и
         автоудаление пустой комнаты.
      4. Цикл фокус-сессии и задачи: старт таймера с задачей, запрет второй параллельной
         сессии (409), пауза, продолжение, досрочное завершение (?force=true) и закрытие задачи.
      5. Полное прохождение таймера по времени, проверка начисления бонусов XP,
         открытия ачивки first_tune_in, роста стрика и 1-го места в лидерборде.

================================================================================

СТУДЕНТ 1 — Архитектура, Пользователи и Коворкинг-комнаты (Workflow 1):
  - Файлы: main.py, core/database.py, core/exceptions.py, models/*,

    прав владельца при выходе создателя.

СТУДЕНТ 2 — Таймеры фокуса и Личные задачи (Workflow 2):
  - Файлы: config.py, schemas/sessions.py, schemas/tasks.py,
    services/session_service.py, services/task_service.py, routers/sessions.py, routers/tasks.py.

    запустить вторую сессию (ошибка 409), паузу/возобновление таймера, досрочное
    или полное завершение сессии и закрытие задачи.

    routers/tracks.py, routers/leaderboard.py, tests/test_api.py.
  - Что показывает в Swagger:
    Каталог музыки (/tracks), смену трека в комнате, работу алгоритма адаптивных
    рекомендаций (/rooms/{id}/recommended-tracks в фазе focus и break), начисление
    XP/уровней/стриков/ачивок и глобальный лидерборд (/leaderboard).

   cd ~/Desktop/focusradio

   http://localhost:8000/docs

4. Запустить автотесты:
   python3 tests/test_api.py
